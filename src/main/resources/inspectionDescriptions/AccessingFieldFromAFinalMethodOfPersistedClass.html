Reports final methods that use a field directly, in classes marked with @Entity, @MappedSuperclass or @Embeddable.

This is almost always a bug, and it fails silently. To load data only when it's needed ("lazy loading"), Hibernate creates a subclass of your class, called a proxy, and its fields are always empty. The proxy can't override a final method, so when you call that method on a proxy, it reads the proxy's empty fields. You get null, 0 or false instead of the real value, and no error.

Example:


@Entity
public class Cat {
    private String name;

    public final String getName() {   // Warning
        return name;
    }
}

How to fix it: remove final from the method (the quick-fix does this for you), or don't use fields directly in final methods. For example, call getName() instead of reading name.

Static methods and static fields are not reported, because proxies don't affect them.

When it's OK to ignore the warning: a final getId() can get the id from the proxy, without loading the whole object from the database: 


@SuppressWarnings("AccessingFieldFromAFinalMethodOfPersistedClass")
public final long getId() {
    if (this instanceof HibernateProxy) {
        return (long) ((HibernateProxy) this).getHibernateLazyInitializer().getIdentifier();
    } else {
        return id;
    }
}

The @SuppressWarnings line turns off the warning for this method only.

More information: IntelliJ IDEA issue, Stack Overflow question.
